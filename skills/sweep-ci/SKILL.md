# CI 扫描

成功运行后，把本文件粘贴到 Grok Bot 中：

> 把刚才的流程保存为名为“CI 扫描”的技能。

一个有用的技能要说明来自 [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations) 的六个字段：

## 1. 何时使用

指定仓库的 CI 变红或抖动，主人需要带日志和负责人的失败清单—— 不是一个会重跑、取消或合并的 Bot。


## 2. 所需输入与访问权限

- GitHub 连接器和指定仓库
- 默认分支和时间窗（默认上次扫描以来）
- 可选的 CODEOWNERS 或钉住的负责人映射

## 3. 操作顺序

1. 列出窗口内默认分支和开放 PR 上失败或取消的检查；不要编造 job。
2. 每个不同失败打开日志；引用错误、路径和 job 名。
3. 重复的聚类；统计同一测试失败次数。
4. 从 CODEOWNERS 或 PR 作者建议负责人；不要在 GitHub 上分配。
5. 至多重跑一次，且仅当日志被截断——写下来；绝不跑到绿。
6. 写扫描备忘；不要取消运行、推送、合并或静音必需检查。

## 4. 如何验证结果

每行都引用检查 URL 或日志行；flake 在同一 job 无代码改动先失败后通过时标注，否则写「flake 未知」；没有合并，没有重试循环。


## 5. 返回什么

CI 扫描：失败 job、聚类、日志引用、建议负责人、flake 备注、操作日志；最多记录一次截断日志重跑。


## 6. 什么需要审批

不要在 GitHub 合并、推送或评论；不要取消工作流或改分支保护；不要跑到绿。


在输入框中键入 `/` 来引用已保存的技能。如果没有出现，打开 **设置 → 插件 → 你的插件** 并为本 Bot 启用它。
