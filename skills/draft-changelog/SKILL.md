# 起草变更日志

成功运行后，把本文件粘贴到 Grok Bot 中：

> 把刚才的流程保存为名为“起草变更日志”的技能。

一个有用的技能要说明来自 [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations) 的六个字段：

## 1. 何时使用

自上次标签以来合并的 PR 要变成面向用户的 release notes，而不是周五考古。


## 2. 所需输入与访问权限

- GitHub 仓库
- 上次标签或变更日志小节
- 受众（用户 vs 运维）

## 3. 操作顺序

1. 列出上次标签以来合并的 PR；不要编造 PR。
2. 按 破坏性 / 新增 / 修复 / 内部 分组。
3. 把标题改写成用户语言；PR 编号保留为链接。
4. 点出需要迁移说明的条目。

## 4. 如何验证结果

每条都对应一个已合并 PR 或提交；没有「各类改进」凑数；未发布。


## 5. 返回什么

变更日志 Markdown 草稿，外加作为内部省略的 PR 清单，方便主人按需恢复。


## 6. 什么需要审批

不要发布 GitHub Release 或打标签；未经批准不要在主分支改 CHANGELOG.md。


在输入框中键入 `/` 来引用已保存的技能。如果没有出现，打开 **设置 → 插件 → 你的插件** 并为本 Bot 启用它。
