# 自主性 —— L0 到 L3

精神上借鉴 loop-engineering 的 L1 只报告周。官方 Grok Bot 文档用不同措辞表达同一件事：从读取并准备的工作开始，审查结果，然后添加已批准的动作或例行程序。

| 级别 | 名称 | 第一周？ | 可以做 | 绝不做 |
|-------|------|-----------|-----|----------|
| L0 | 观察 | 是，适用于观察者 | 读取、汇报 | 可发送的草稿 |
| L1 | 草稿 | **默认** | 可审查的成品 | 发送、发布、支付、合并、生产 |
| L2 | 已批准动作 | 草稿被信任之后 | 聊天中批准后执行点名写入 | 任何未点名的动作 |
| L3 | 计划任务 | 两次良好技能运行 + 试跑之后 | 例行程序运行技能 | 写入仍遵循 `approval_never`，除非例行程序点名例外 |

## 公开地升级

把级别放进 Bot **描述**，而不仅仅是置顶消息。描述级规则在新对话中依然存在。消息级规则不会。

当你把 L1 → L2 升级时，点名动作：

> 在我输入「发布」后，你可以发布 GitHub 审查评论。你仍然不能合并。

当你把 L2 → L3 升级时，点名缺失来源策略：

> 如果 GitHub 宕机，报告失败。不要审查昨天的缓存 diff。

## 试跑是真实工作

官方文档：例行程序的**试跑**会浏览网站、修改文件、调用连接器。使用安全输入。即使在试跑中，也把写入置于审批之后。
