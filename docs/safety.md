# 安全

Grok Bot 的设计是在完成工作的同时，把敏感输入和后果重大的动作置于你的控制之下。本目录把它编码为常设 `approval_never` 清单。

## 每个模板的硬性规则

- YAML 或 PROFILE.md 中不含 API 密钥、令牌、客户数据或内部 URL
- 默认 L1
- `share_safe: true`
- 共享电脑**不是**安全边界（[电脑与应用](https://docs.x.ai/grok-bot/computer-and-apps)、[审批](https://docs.x.ai/grok-bot/approvals-security-and-privacy)）
- 密码、两步验证、验证码、付款：主人接管电脑。绝不把验证码粘贴到聊天里
- 生产、发送、支付、合并、发布、删除都留在审批之后

## 自动审查

如果「自动审查」可用，为发送邮件和改动生产添加**需要审批**规则。需要审批胜过始终允许。不要写「允许浏览器中的所有操作」。

## 本地电脑

默认是每次都询问。除非某个 Bot 有具体理由触碰你面前的 Mac/Windows 机器，否则使用**永不允许**。云电脑访问是单独的。

## 分享

公开分享链接复制身份、描述、技能和例行程序。它不复制你的电脑或登录。接收者接受[第三方 Bot 条款](https://x.ai/legal/bot-sharing-terms)。复制链接之前运行 **Share Sanitizer** Bot。

## 最小权限

只连接工作流需要的工具。从只读开始。来源系统变更时暂停例行程序。保留来源链接和操作日志。

## 本仓库不会发布

- 无人值守的生产改动者
- 作为 L3 的「它能买」购物 Bot
- 宽泛的事件监听器（「每条新 Slack 消息」）
- 把额外 Bot 当作隔离的模板
